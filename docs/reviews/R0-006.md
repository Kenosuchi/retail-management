# R0-006 final review

**Reviewed:** 2026-10-02

**Disposition:** Approved for the local Docker Compose foundation scope.

## BLOCKER

None. The persistence check no longer creates or deletes a database table. Its
subshell exits on command failure and requires nonempty MySQL UUID values before
comparing them.

## MAJOR

None. The outage check requires a nonempty backend start time, observes the
expected health responses, waits for recovery, and verifies that the backend
process did not restart. MySQL startup is attempted by an exit trap if the
outage check fails. The readiness request allows enough time for database
connection failure to be reported while retaining a bounded number of attempts.

## MINOR

None requiring correction before acceptance.

## SUGGESTION

Keep this Compose definition focused on local integration. Staging and
production deployment, secret storage, backup and restore, and monitoring need
their own requirements and release work.

## Implementation reviewed

- One Angular frontend, one Spring Boot modular monolith, and one MySQL 8.4.11
  service. The frontend has no startup dependency on the backend; the backend
  waits for MySQL health before starting.
- Patch-specific Node 22, Java 25, and Nginx base images. Backend and frontend
  runtime images use non-root users and build contexts exclude generated and
  local environment files.
- Backend and frontend ports bind to the host loopback interface. MySQL has no
  host port. A named volume stores MySQL's data directory.
- Health checks cover MySQL, backend readiness, and the frontend HTTP server.
  Nginx serves Angular routes through the SPA fallback while missing static
  assets return HTTP 404.
- A local runbook covers setup, health, logs, bounded checks, database outage,
  recovery, persistence, and the distinction between normal shutdown and
  destructive volume removal.

## Verification evidence

`docker compose -f infra/docker-compose.yaml config --quiet` passed. With an
empty environment file, configuration failed and named the missing database
variables. `git diff --check` and Bash syntax checking of the runbook commands
passed.

An isolated Compose project, `retail-r0006-audit`, used the same service images
and configuration with host port publishing removed. Its own MySQL named volume
was created for this review; the existing developer stack was not interrupted.
`up --build --wait --wait-timeout 120` built both images and reached healthy
status for all three services.

The isolated lifecycle check produced:

```text
before outage: backend readiness=200
during outage: liveness=200 readiness=503
after recovery: readiness=200, backend start time unchanged
after normal down/up: MySQL server UUID unchanged
```

The first outage probe used a five-second readiness request and timed out before
the database connection failure was reported. A 40-second per-request limit
observed HTTP 503 on the first attempt. The runbook now uses that limit and at
most four attempts. MySQL's `auto.cnf` UUID was nonempty and equal before and
after normal container recreation, establishing that the same MySQL-managed
data directory was reused. This does not assert a business-row round trip; R0
has no production business tables. The R0-004 Testcontainers suite covers a
database write/read round trip independently.

`./mvnw -q clean verify` passed with Java 25 and MySQL Testcontainers: 16 tests,
zero failures, errors, or skips. `npm run verify` passed formatting, all 6
Vitest tests across 4 files, and the Angular production build. The frontend
route assertions run in Vitest; no browser end-to-end framework exists in R0.

Approval applies to the current working tree. R0-006 changes are not yet
committed.

## Learning checkpoints

- Explain why a named volume survives container recreation and why `down -v`
  deletes the local database state.
- Distinguish a process being live from its ability to serve database-backed
  requests; explain why only readiness depends on MySQL.
- Explain why a bounded retry loop also needs a timeout on each request and why
  a verification command must reject empty observations.
- Explain why a passing image build does not replace the backend and frontend
  test suites.
