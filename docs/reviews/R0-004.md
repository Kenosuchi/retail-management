# R0-004 final review

**Reviewed:** 2026-09-13

**Disposition:** Approved. The R0-004 acceptance criteria are satisfied.

## BLOCKER

None.

The earlier hardcoded datasource credentials were removed. Runtime connection
details now come from Spring Boot's standard external configuration variables.
The out-of-scope Compose draft is absent from the R0-004 changeset.

## MAJOR

None.

The earlier readiness and persistence-boundary findings are resolved. Readiness
contains `readinessState` and `db`, liveness contains only `livenessState`, and
Open EntityManager in View is disabled.

## MINOR

None. The final text-file formatting issue in `application.properties` was
resolved before final review.

## SUGGESTION

Java 25 reports native-access and Mockito dynamic-agent warnings during the test
run. They do not affect current behavior. Review explicit test-JVM configuration
if a later JDK makes either warning an error; do not suppress tests to hide them.

## Implementation reviewed

- Spring Data JPA, Flyway, the MySQL Flyway module, and Connector/J are managed
  through Spring Boot's dependency set; database-specific modules have runtime
  scope.
- Flyway is the schema owner, SQL initialization is disabled, Hibernate validates
  rather than mutates the schema, and Flyway clean is disabled.
- A Spring-managed Testcontainers MySQL 8.4.11 instance supplies connection
  details to the full application context through `@ServiceConnection`.
- The generated test password and non-root account keep tests isolated from a
  developer database.
- Test-only migration V0 creates the persistence smoke fixture. Production
  migrations remain ready to start at V1 with the first domain schema.
- JUnit tests cover MySQL identity, Flyway history and validation, JDBC write/read
  behavior, persistence-context boundaries, health membership, endpoint privacy,
  and the original security contract.
- ADR-0004 records MySQL 8.4 LTS as the supported server line. Setup, migration,
  architecture, and toolchain documentation reflect the implemented state.

## Verification evidence

`./mvnw clean verify` completed successfully with Java 25 and a
disposable MySQL 8.4.11 container: 16 tests passed with no failures, errors, or
skips. No application-setting overrides were used.

The packaged application failed to start when datasource configuration was
absent and failed with MySQL error 1045 when given an invalid password. This
confirms that it does not silently select an embedded or workstation database.
The invalid-credential diagnostic did not print the supplied password.

An end-to-end outage check produced:

```text
healthy liveness=200 readiness=200
outage  liveness=200 readiness=503
```

Archive inspection confirmed that V0, test classes, and Testcontainers libraries
are absent from the executable JAR. Flyway and Connector/J are present.
`git diff --check` passed.

## Learning checkpoints

- Hibernate mapping validation and Flyway checksum validation prove different
  properties; neither replaces migration review.
- Real MySQL tests establish driver, dialect, and migration behavior that Mockito
  tests cannot establish.
- A persistence context controls managed entity state; it is not itself the
  database transaction boundary.
- Failed readiness removes an unusable instance from traffic. Failed liveness
  would ask the platform to restart an otherwise healthy process during a shared
  database outage.
